Concept of Deadlocks

Definition Causes Simulation Prevention

What is a Deadlock?

A deadlock occurs when two or more processes are waiting for resources held by each other, causing all processes to stop indefinitely; It's like a digital traffic jam where every process is waiting and none can proceed.

What Causes Deadlocks?

A deadlock happens only when four certain conditions occur all at the same time. If one of these conditions is broken, the deadlock cannot occur. The four conditions that are considered the main causes of deadlocks are:

1- Mutual Exclusion
certain resources can only be used by one process at a time. If another process requests a resource being used, it must wait and be delayed until the current process finishes using it and releases it.
2- Hold and Wait
A process may be holding a resource while waiting for an additional resource that is currently being used by other process.
3- No Preemption
Once a process has access to a resource, then the system cannot forcefully cause an interrupt and give the resource away. The process must voluntarily release the resource on its own after completing its task.
4- Circular Wait
When multiple processes are stuck in a cycle of waiting, where each process is waiting for a resource held by the next process, this creates an endless chain.

How Can Deadlocks Be Prevented?

Deadlocks can be avoided by making sure at least one of the four conditions required for a deadlock never happens. The operating system changes how resources are requested and shared so processes do not end up waiting on each other.

Some common strategies used to prevent deadlocks include:

  • Having a process request all the resources it needs at the beginning, which avoids waiting for extra resources later.
  • Following a fixed order when requesting resources, reducing the chance of processes blocking one another.
  • Allowing the system to temporarily take resources away from a process if needed.

A Closer Look at Deadlock Prevention Methods:

1- Removing the Hold and Wait Condition
By giving a process all the resources it needs before it even starts execution ensures that it does not need to wait for additional resources later. However, this can reduce efficiency because some resources may stay unused for a long time.
2- Allowing Resource Preemption
The operating system can temporarily take a resource from one process and reassign it to another process that may need it more urgently. The interrupted process can continue later once the resource is free again.
3- Enforcing Resource Ordering
By arranging resources in a specific order of priority, the processes that need them must request them in a sequence which helps in preventing circular waiting. This method ensures a process can not request a process that is already being used by another process.
4- Reducing Mutual Exclusion
Resources are designed to be shareable among multiple processes where it is allowed instead of resources being locked by one process at a time. This prevents a process from exclusively having a resource unnecessarily and this helps the system run more smoothly.
