CPU Scheduling — Topic 03

Priority Scheduling
[ Preemptive ]

Interactive Simulator & Visual Explainer

// Theory

Priority Scheduling assigns each process a numerical priority. The CPU is always given to the process with the highest priority (lowest number = highest priority, by convention). In the preemptive version, if a new process arrives with a higher priority than the currently running process, the CPU is immediately taken away from the running process and given to the newcomer.

⚡ Preemption means the OS can interrupt a currently executing process mid-burst if something more urgent arrives. The preempted process goes back to the Ready Queue to wait its turn again.

This algorithm is also known as Preemptive Priority Scheduling or Priority-Based Preemptive Scheduling. It is widely used in real-time systems where urgent tasks must not wait.

🏆

Selection Rule

At every time unit, the process with the highest priority (lowest number) in the ready queue runs.

⚡

Preemption

A newly arrived process with higher priority immediately preempts the current process.

💀

Starvation Risk

Low-priority processes may never execute if high-priority processes keep arriving. Fixed by "aging".

⏱️

Overhead

Frequent context switches due to preemption add overhead compared to non-preemptive variants.
