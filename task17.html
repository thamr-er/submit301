Understanding Concurrency

Learning how computer processors manage multiple jobs at once

1. What is Concurrency?

Concurrency means that an operating system is dealing with multiple tasks during the same time frame. It does not mean they are running at the exact same split-second. Instead, a single processor core jumps back and forth between different programs incredibly fast, which creates the illusion that everything is running at once.

To do this, the OS uses a Scheduler. If one program pauses to wait for a file to open or a webpage to load, the CPU saves its place (this is called a Context Switch) and starts working on a different task so no time is wasted.

This is different from Parallelism. Concurrency is about scheduling and juggling multiple jobs on a single CPU core. Parallelism means you have multiple physical CPU cores running separate tasks at the literal same time.

The Cooking Analogy: Think of a single chef in a kitchen. They put water on to boil for pasta, and while they wait for it to get hot, they chop vegetables. They are only doing one physical thing at a time, but they are working on two dishes concurrently. If another chef joins the kitchen to cut vegetables while the first chef stirs the pot, that is parallelism.

2. Common Juggling Problems

🏁 Race Conditions

Two separate tasks try to change the same global variable at the exact same time, causing them to overwrite each other's progress and lose data.

🔒 Deadlocks

Task A is waiting for a file held by Task B, while Task B is waiting for a file held by Task A. Both freeze permanently because neither will let go.

⏳ Starvation

A low-priority task sits in line forever because high-priority tasks keep jumping to the front of the queue.
