Direct Memory Access

Hardware-level data transfers — bypassing the CPU

Core Concepts
🖥️

Without DMA (PIO)

In Programmed I/O, the CPU manually reads each byte from a device register and writes it to memory — one byte at a time. The CPU is fully occupied for the duration of the transfer, unable to do any other work. This is called busy-waiting or polling.

⚡

With DMA

The DMA Controller is a dedicated hardware chip that takes over the data bus. The CPU tells the DMA controller: "transfer N bytes from device X to address Y", then the CPU is free to execute other processes while the DMA handles the transfer autonomously.

🔌

The System Bus

All components (CPU, Memory, I/O devices) share a common system bus. During a DMA transfer, the DMA controller requests bus mastership. The CPU yields the bus temporarily — called cycle stealing — allowing the DMA to perform the transfer.

🔔

Interrupt on Completion

When the DMA controller finishes the entire transfer, it sends a hardware interrupt to the CPU. Only at this point does the CPU need to respond — to acknowledge completion and handle the transferred data. This is vastly more efficient than polling.

PIO vs DMA — Transfer Comparison
Aspect Without DMA (PIO) With DMA
CPU involvement Every single byte Only setup + interrupt
CPU during transfer Blocked / polling Free to run other processes
Transfer speed Limited by CPU speed Near memory-bus speed
Interrupts generated One per byte (or word) One per entire transfer
Use case Small, infrequent transfers Disk I/O, network, audio, video

How DMA Works — Step by Step
01
CPU Initiates: The CPU writes the source address, destination address, and byte count into the DMA controller's registers. Then the CPU issues a "start" command.
02
CPU Freed: The CPU immediately returns to executing other instructions or processes. It does not wait for the transfer.
03
DMA Requests Bus: The DMA controller asserts a Bus Request (BR) signal. The CPU responds with Bus Grant (BG) and briefly yields control of the address/data bus.
04
Cycle Stealing: The DMA reads from the I/O device buffer and writes directly to memory, one word at a time, stealing bus cycles from the CPU with minimal impact.
05
Transfer Complete: Once all bytes are moved, the DMA controller raises an interrupt line to the CPU, signaling the transfer is done.
06
CPU Handles ISR: The CPU briefly pauses its current task to run the Interrupt Service Routine (ISR) — acknowledging the transfer and processing the data in memory.
