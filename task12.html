Linker & Loader
Explained

How source code travels from text files to running processes — step by step.

01 — Definitions

What are they?

Linker

A system tool that takes multiple object files (.o) produced by the compiler and combines them into a single executable. It resolves all symbolic references when file A calls a function defined in file B, the linker finds that function's address and patches it in. It also appends any required static libraries, strips dead code, and assigns final virtual memory addresses to every symbol.

Loader

Part of the operating system that takes a finished executable file and brings it to life. It reads the file's segments (code, data, BSS), allocates virtual memory pages, copies each segment into the right location, resolves any remaining dynamic library references at runtime, and finally hands control to the program's entry point (_start or main).

02 — Differences

Side by side

Linker Loader
Runs at compile time (before the program executes) Runs at runtime (when you launch the program)
Input: multiple object files (.o) and libraries (.a / .lib) Input: a single fully linked executable (.exe / ELF)
Output: a single executable or shared library Output: a live, running process in memory
Resolves symbolic references between translation units Resolves dynamic library calls (e.g. libc, .dll, .so)
Performs static relocation — fixes addresses in the file Performs load-time relocation — adjusts addresses for ASLR
Merges .text, .data, .bss sections from all object files Maps those merged sections into virtual memory pages
Produces the program headers and segment layout in the file Reads program headers to know what to put where
Can perform link-time optimisation (LTO) across files Can perform dynamic optimisation via JIT in managed runtimes

04 — Functions

Key operations

// Linker functions

01

Symbol resolution

Matches every undefined symbol reference in one .o file to a definition found in another .o or library file.

02

Relocation

Updates all placeholder addresses (0x0000) that the compiler emitted with correct final virtual addresses in the output binary.

03

Section merging

Combines all .text sections into one, all .data sections into one, and so on, building the final memory image of the program.

04

Dead code elimination

With LTO enabled, the linker can discard functions and data that are never referenced, shrinking the output binary.

05

Library inclusion

Searches static libraries (.a) for any object file that satisfies an unresolved symbol, pulling in only what is needed.

06

Entry point setup

Writes the address of the program entry point (_start) into the ELF header so the OS knows where execution begins.

// Loader functions

01

Validation

Reads the ELF/PE magic bytes and headers to confirm the file is a valid executable for the current architecture and OS.

02

Memory mapping

Calls mmap() to create virtual memory regions for each segment, backed by the file on disk — no full copy needed initially.

03

Dynamic linking

Invokes the dynamic linker (ld.so) to locate and map shared libraries, then fills the GOT/PLT with real addresses.

04

ASLR relocation

With Address Space Layout Randomisation, the loader shifts all segment base addresses by a random offset at each launch for security.

05

Stack & heap init

Allocates the initial stack, pushes argc, argv, and environment pointers, and sets up the heap boundary for future malloc calls.

06

Execution handoff

Jumps to the binary's entry point. On Linux this is _start, which calls __libc_start_main, which then calls main().
