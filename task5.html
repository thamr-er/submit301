How does the OS decide when a process gives up the CPU — voluntarily, or by force?

Topic

CPU Sched.
The Core Question
In any operating system, multiple processes compete for one (or a few) CPU cores. The scheduler decides which process runs next. But there is a deeper question: once a process starts running, can the OS interrupt it mid-execution? The answer splits all scheduling algorithms into two fundamental families — Preemptive and Non-Preemptive. Understanding this distinction is the key to understanding every scheduling algorithm you will ever study.
Side by Side
⚡

Preemptive
Scheduling

FORCEFUL

The OS can forcibly remove a running process from the CPU at any time — typically when a higher-priority process arrives or a time quantum expires. The interrupted process goes back to the ready queue and will resume later.

  • CPU can be taken away mid-burst
  • Requires context saving on every switch
  • Better response time for urgent tasks
  • Risk of race conditions on shared data
  • Used in: Round Robin, Preemptive Priority, SRTF
  • Found in: Linux, Windows, macOS (all modern OSes)
🔒

Non-Preemptive
Scheduling

COOPERATIVE

Once a process starts running, it holds the CPU until it finishes or voluntarily yields (e.g. waiting for I/O). No other process can interrupt it. The scheduler only picks a new process when the current one is done.

  • CPU held until burst complete or I/O wait
  • Simpler — no mid-burst context saves
  • Predictable execution, no race conditions
  • Poor responsiveness for short urgent tasks
  • Used in: FCFS, SJF (non-preemptive), Non-Preemptive Priority
  • Found in: older batch systems, embedded systems

Feature Comparison
Criterion ⚡ Preemptive 🔒 Non-Preemptive
CPU allocation Can be forcibly reclaimed anytime Held until process yields or finishes
Response time Low — urgent tasks run quickly High — must wait for current process
Overhead Higher — frequent context switches Lower — fewer context switches
Starvation risk Possible (low-priority waits) Possible (long process blocks others)
Complexity More complex — needs synchronization Simpler — straightforward flow
Best for Interactive, real-time, general-purpose Batch processing, predictable workloads
Examples Round Robin, SRTF, Preemptive Priority FCFS, SJF, Non-Preemptive Priority
Real-World Analogies
⚡ Preemptive
Like a hospital emergency room — if a critical patient arrives while a doctor is treating a minor injury, the doctor stops and immediately switches to the emergency. The minor case resumes later. The urgency determines who gets the resource right now.
🔒 Non-Preemptive
Like a bank teller — once a customer is being served, the teller must finish that transaction completely before calling the next customer, even if a VIP walks in. Everyone waits in line no matter what.
⚡ Context Switch
When preemption happens, the OS saves everything about the current process (registers, program counter, stack) into its PCB (Process Control Block) so it can resume exactly where it left off — like using a bookmark mid-chapter.
🔒 Cooperative Trust
Non-preemptive scheduling is sometimes called "cooperative" — the OS trusts each process to be well-behaved and yield the CPU eventually. One misbehaving process can freeze the entire system — a famous flaw of early Windows (3.x era).
