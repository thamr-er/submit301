Topic 7 — OS Concepts

Process Control Block

// The kernel's complete record of every process in the system

01 — What Is a PCB?

When an operating system creates a process, it must keep track of everything about that process — its current state, where it is in memory, which files it has open, and exactly what it was doing before the CPU was handed to another process. All this information is stored in a data structure called the Process Control Block (PCB).

The PCB is sometimes called a Task Control Block (TCB) or process descriptor. In the Linux kernel, it is implemented as the task_struct structure. There is one PCB per process, and the OS maintains a table of all PCBs (the process table).

The PCB is the key mechanism that makes context switching possible: when the CPU switches from one process to another, the OS saves the current process's state into its PCB, then loads the next process's state from its PCB — so execution can resume exactly where it left off.

WHY IT MATTERS
The PCB is the identity card of a process. Without it, the OS would have no way to resume a process after switching away, no way to enforce memory boundaries, and no way to manage file access or priorities.
IN LINUX KERNEL
Linux stores PCB data in struct task_struct, defined in <linux/sched.h>. It contains over 100 fields. Each process in the system has exactly one of these.
STORED IN KERNEL SPACE
The PCB lives in kernel memory, not user memory. Processes cannot directly access or modify their own PCB — only the OS kernel can.
03 — Key PCB Fields Explained
🔢
Process ID (PID)
A unique integer that identifies the process. Assigned by the OS on creation. The parent's PID is stored as PPID.
🔄
Process State
Current state: New, Ready, Running, Waiting, or Terminated. The OS uses this to manage scheduling decisions.
📍
Program Counter (PC)
Address of the next instruction to execute. Saved here during context switches so the process can resume correctly.
🧮
CPU Registers
Snapshot of all CPU registers (AX, BX, SP, etc.) at the time the process was last paused. Restored on resume.
📊
Scheduling Info
Priority level, scheduling queue pointers, CPU time used, and time remaining in its current time quantum.
🗺️
Memory Management
Base address, limit registers, and pointer to the page table. Defines the process's virtual address space.
📂
I/O & File Info
List of open file descriptors, I/O devices allocated to this process, and pending I/O requests.
📈
Accounting Info
CPU time consumed, real (wall-clock) time elapsed, and usage limits. Used for billing and resource enforcement.
04 — How Context Switching Uses the PCB
01
Interrupt or System Call Occurs
The CPU receives a timer interrupt (or the running process makes a blocking system call), triggering the OS scheduler.
02
Save Current Process State → PCBA
The OS saves the Program Counter, all CPU register values, and the process state into Process A's PCB. Process A is moved from Running → Ready (or Waiting).
03
Scheduler Selects Next Process
The OS scheduler picks Process B from the Ready Queue based on the scheduling algorithm (FCFS, SJF, Priority, etc.).
04
Restore Process State from PCBB
The OS loads Process B's saved Program Counter and register values from its PCB back into the CPU. Process B's state becomes Running.
05
Process B Resumes Execution
The CPU picks up exactly where Process B left off. From B's perspective, nothing happened — it just continued running.
