// 01 — What Is Threading?

A thread is the smallest unit
of CPU execution

A thread (also called a lightweight process) is an independent sequence of instructions that can be scheduled and executed by the CPU. Every process starts with one thread (the main thread), but can spawn additional threads that share the same code, data, and heap memory — while each maintains its own private stack, program counter, and register set.

Threading enables concurrency: the CPU rapidly switches between threads giving the illusion of simultaneous execution, and on multi-core systems enables true parallelism — multiple threads literally running at the exact same moment on different cores.

Process
🗂️

Process

  • Heavyweight — large overhead to create
  • Has its own isolated memory space
  • Communication requires IPC (pipes, sockets…)
  • Crash of one does not affect others
  • Context switch is expensive
🧵

Thread

  • Lightweight — fast and cheap to create
  • Shares memory with sibling threads
  • Communication is simple — shared variables
  • A crash in one thread can crash the process
  • Context switch is very fast
// 02 — Anatomy of a Multi-Threaded Process

What threads share and
what they own

Inside a single process, all threads share the code segment, data segment, heap, and open file descriptors. Each thread, however, must maintain its own execution context — its private stack (for local variables and function calls), its own program counter (where it's currently executing), and its own copy of the CPU registers.

// 05 — Threading Models

How user threads map to
kernel threads

The OS kernel manages its own threads. User-level threads must be mapped to kernel threads to actually run on the CPU. There are three classic models for this mapping.

Many-to-One

Many user threads map to a single kernel thread. Simple but if one thread blocks, all block. No true parallelism.

One-to-One

Each user thread maps to its own kernel thread. True parallelism. Used by Linux and Windows. More overhead.

Many-to-Many

Many user threads multiplex over many (but ≤ equal number of) kernel threads. Best of both worlds. Complex to implement.
