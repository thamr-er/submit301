01 — Core Concepts

What is Virtual Memory?

Virtual Memory is an abstraction that gives each process the illusion of having its own large, contiguous address space — even if the actual physical RAM is smaller or fragmented. The OS and hardware work together to translate virtual addresses (used by programs) into physical addresses (actual RAM locations).

What is Paging?

Paging is the mechanism that implements virtual memory. Both the virtual address space and physical memory are divided into fixed-size blocks. Virtual blocks are called pages. Physical blocks are called frames. Pages are mapped to frames via a page table.

Why Paging?

Without paging, programs must fit entirely in contiguous RAM. With paging: processes can be larger than physical RAM, multiple processes share RAM safely without interference, and memory fragmentation is eliminated because any frame can hold any page.

Address Structure

A virtual address is split into two parts by the CPU:

Virtual Address = [ Page Number | Page Offset ]

Physical Address = [ Frame Number | Page Offset ]

Page Size = 2^(offset bits) bytes

Key Terminology

Page Table — A per-process data structure maintained by the OS. Each entry maps a virtual page number to a physical frame number, plus a valid bit.

Page Fault — Occurs when the CPU accesses a page whose valid bit is 0 (not currently in RAM). The OS must load the page from disk (swap space) into a free frame and update the page table.

TLB (Translation Lookaside Buffer) — A hardware cache inside the CPU that stores recent page→frame translations to speed up address translation without hitting the page table in RAM every time.

04 — Page Fault Handling

What Triggers a Page Fault?

When the CPU tries to access a virtual address whose valid bit in the page table is 0, the hardware raises a page fault interrupt. This means the page is not currently loaded in RAM — it lives on disk (swap space).

The Steps to Handle It

1
CPU triggers page fault trap → control goes to OS kernel.
2
OS checks if the address is valid (in the process's virtual space). If not → segfault.
3
OS finds a free frame in RAM (or evicts one using a replacement algorithm like LRU).
4
OS reads the page from disk into the free frame.
5
OS updates the page table: sets frame number, valid bit = 1.
6
Process resumes at the faulting instruction, which now succeeds.
05 — Summary & Key Takeaways

Advantages of Paging

✦ No external fragmentation (fixed-size pages fit any frame)

✦ Processes can be larger than physical RAM

✦ Easy memory protection (each page table entry has protection bits)

✦ Efficient sharing (multiple processes can map the same physical frame)

Disadvantages / Trade-offs

✦ Internal fragmentation in the last page of a process

✦ Page table itself consumes memory (mitigated by multi-level tables)

✦ Two memory accesses per instruction without TLB (page table + data)

✦ Page faults cause expensive disk I/O (thrashing if RAM is too small)

The Formula to Remember

Given: Virtual Address (VA), Page Size (P)

Page Number (p) = VA ÷ P  (integer division)
Page Offset (d) = VA mod P

Physical Address = (PageTable[p].frame × P) + d

Number of pages = Virtual Address Space Size ÷ Page Size
Number of frames = Physical Memory Size ÷ Page Size
