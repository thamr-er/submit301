dup() and dup2()

// File Descriptor Duplication — Linux System Calls
Overview

In Linux, every open file, socket, or pipe is referred to by an integer called a File Descriptor (FD). Every process starts with three standard descriptors: stdin (0), stdout (1), and stderr (2).

The dup() and dup2() system calls create a copy (duplicate) of an existing file descriptor. Both the original and the copy refer to the same underlying open file — they share the same file offset and status flags. Closing one does not close the other.

These calls are essential for implementing I/O redirection in shells (e.g., ./program > output.txt) and for setting up pipes between processes after fork().

I/O Redirection Pattern — Shell Implementation
// Shell wants to run: ./program > output.txt
// ------------------------------------------------
int fd = open("output.txt", O_WRONLY|O_CREAT|O_TRUNC, 0644);
// fd is now, say, 3 → points to output.txt

dup2(fd, 1);
// Now stdout (fd=1) ALSO points to output.txt

close(fd);
// Close original fd=3; fd=1 still valid

execvp("./program", args);
// program's printf() goes to output.txt ✓

Because dup2(fd, 1) atomically closes old fd 1 and replaces it with a copy pointing to the same file as fd, any writes to stdout by the child process now go to the file instead of the terminal. This is how every Unix shell implements the > operator.
